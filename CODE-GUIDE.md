# Code guide for new developers

This guide explains how the TIRYAQ code is organised, so you can find your way around even if you are new to ASP.NET Core.

Every file starts with a short comment that says what it is for:

- C# and JavaScript files: a `// ...` line above the class or at the top.
- Views (`.cshtml`): an `@* ... *@` line at the top saying which page it is and which controller action shows it. Razor comments are never sent to the browser.
- Stylesheets (`.css`): a `/* ... */` line saying which pages use it.

## 1. What the app does, in one paragraph

A **department** asks to buy something (a *purchase request*). A **sourcing officer** reviews it and turns it into a
*tender*, then invites **suppliers**, who send *offers* (also called *bids*). The officer checks each offer meets the
rules (*compliance*). The **Evaluation Committee** (4 people) scores the offers and recommends a winner. The
**Sourcing Manager** reviews that recommendation and sends it to the **CEO & Chiefs** (the *Top Committee*, 4 people),
who vote. When all four approve, the tender is *awarded* to the winning supplier. An **Admin** manages accounts.

## 2. The technology

| Piece | What it is | Where to learn |
|---|---|---|

| Razor views (`.cshtml`) | HTML pages with small bits of C# (`@Model.Title`). | Same tutorial |

## 3. Folder map

| Folder | What is inside |
|---|---|
| `Controllers/` | One controller per area (Department, SourcingOfficer, Supplier...). Each public method is a page or a form post. |
| `Views/` | The pages. `Views/Department/Create.cshtml` is the page for `DepartmentController.Create`. `Views/Shared/` holds pieces used everywhere, such as the layout and partial views (files starting with `_`). |
| `Models/` | Classes that carry data to and from pages (*view models*). |
| `Models/Entities/` | One class per database table (`Tender`, `Bid`, `PurchaseRequest`...). |
| `Data/` | The database connection (`ApplicationDbContext`), user accounts, role names, and `Migrations/` (the history of database changes, generated by EF Core: do not edit by hand). |
| `Services/` | The business logic and anything too big for a controller: AI, reports, Top Committee rules, face sign-in, PDF watermarks. |
| `ViewComponents/` | Small reusable page parts that load their own data (notification bell, offer photos, QR code). |
| `Contracts/` | Interfaces (the list of methods a service must provide) and the error types (exceptions) for the CEO & Chiefs services. Controllers depend on these interfaces, which makes them easy to test. |
| `wwwroot/` | Files sent straight to the browser: `css/`, `js/`, `images/`. `wwwroot/lib/` is third-party code: do not edit. |
| `Checks/` | Self-test programs. They are not unit tests; you run them from the command line (see section 7). |
| `scripts/` | Helper scripts, such as creating the first admin account. |
| `docs/` | Design notes from earlier phases. |

`Program.cs` is where the app starts: it registers services, sets up sign-in and roles, and maps the URLs.

## 4. Follow one request through the code

Example: a department user opens **New request** and submits the form.

1. The browser asks for `/Department/Create`.
2. ASP.NET Core finds `DepartmentController` and its `Create()` method (the URL pattern is `/{controller}/{action}/{id?}`).
3. `[Authorize(Roles = RoleNames.Department)]` at the top of the controller makes sure only department users get in.
4. `Create()` returns `View("RequestForm", ...)`, which renders `Views/Department/RequestForm.cshtml`.
   (Usually a view has the same name as the action; here the form page is shared by Create and Edit.)
5. The user fills the form and presses **Submit**. The browser posts to `/Department/Create`; the `[HttpPost]` version of `Create` receives a `PurchaseRequestForm` (in `Models/`).
6. The action checks `ModelState.IsValid` (the validation rules on the form class). If something is wrong it shows the form again with the errors.
7. Otherwise it builds a `PurchaseRequest` entity, adds it with `db.PurchaseRequests.Add(...)`, saves it with `db.SaveChangesAsync()`, and notifies the sourcing officers, all inside one database transaction.
8. It puts a success message in `TempData` and redirects to the request's details page (`RedirectToAction(nameof(Details), ...)`), so refreshing the page does not submit twice.

Every workspace works the same way: controller action, then view, with entities saved through `db`.

## 5. Who uses which controller

| Role | Controller | Sidebar menu defined in |
|---|---|---|
| Admin | `AdminController` (split into `AdminController.*.cs`), `ReportAccessController` | `Models/PageNavigation.cs` |
| Department | `DepartmentController` | same |
| Sourcing Officer | `SourcingOfficerController` (split into `SourcingOfficerController.*.cs`) | same |
| Evaluation Committee | `EvaluationCommitteeController` | same |
| Sourcing Manager | `SourcingManagerController` | same |
| CEO & Chiefs | `TopCommitteeController` | same |
| Supplier | `SupplierController` | same |
| Everyone signed in | `AccountController`, `ClarificationController`, `AiIntelligenceController`, `AiChatController`, `ReportsController` | |
| Public visitors | `HomeController`, `PublicSafiController` | |

**Why is one controller split over several files?** C# lets a class be `partial`: the same class written across several
files. Large controllers are split by topic (for example `SourcingOfficerController.Pdf.cs` holds only the PDF downloads).
It is still one controller with one URL prefix.

## 7. Run it and check it

See [LOCAL-SETUP.md](LOCAL-SETUP.md) for the full setup. In short:

```powershell
dotnet ef database update
dotnet run --launch-profile https
```

Then open https://localhost:7130.

The self-test programs in `Checks/` run with an argument instead of starting the website:

```powershell
dotnet run -- --self-test
dotnet run -- --supplier-workflow-checks
dotnet run -- --top-committee-foundation-check
dotnet run -- --reports-data-checks
dotnet run -- --supplier-link-checks
```

`--product-photo-checks` also needs the app already running on https://localhost:7130.

## 8. Words used in the code

| Word | Meaning |
|---|---|
| Bid / offer | A supplier's answer to a tender. Same thing. |
| Compliance | The officer's yes/no check that an offer meets the tender rules. |
| Clarification | A short question-and-answer thread between two people about a request, tender or offer. |
| Top Committee / CEO & Chiefs | The final four-person approval committee. |
| Round | A tender's offer period. A second round extends the deadline. |
| `db` | The `ApplicationDbContext` passed into controllers and services: the object used to read and save database rows. |
