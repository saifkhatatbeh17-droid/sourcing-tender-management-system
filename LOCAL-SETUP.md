# Tiryaq local setup for AI agents

Use this checklist when a teammate asks you to set up or run the checkout after pulling. The steps below are for Windows PowerShell, from the repository root.

1. **Check the machine and checkout.** Verify the intended branch and inspect the working tree. Check for the .NET 10 SDK, an available SQL Server or LocalDB instance, and Python 3.12 if local voice is requested. Reuse a healthy Tiryaq or voice instance instead of launching a duplicate.
2. **Merge local settings.** Follow [SQL Server and Groq settings](VLLM-SETUP.md#step-2--configure-sql-server-and-groq). Preserve existing settings and choose the teammate's local development database. Use their existing Groq key if configured. If it is missing, ask them to add their own key in the Git-ignored `appsettings.Local.json` and continue with independent setup. Never print or commit the key. Set `Speech:Local:Enabled` to `true` for Chatterbox.
3. **Restore and migrate.** If `.config/dotnet-tools.json` is absent, create `.config` and copy the tracked root `dotnet-tools.json` into it. Run `dotnet tool restore`, `dotnet restore`, and `dotnet ef database update` against the verified local database. Reuse existing logins. For a fresh database, run `scripts/create-admin.ps1` with the teammate's chosen email and let them enter their password privately. A pull does not copy demo accounts or tender records.
4. **Start Chatterbox for the same voice.** Use a Python 3.12 virtual environment outside the repo, for example `py -3.12 -m venv "$env:LOCALAPPDATA\Tiryaq\safi-voice"`. Use that environment's Python to run `-m pip install -r scripts/requirements-safi-local-speech.txt`, then run `scripts/safi-local-speech.py` with it. Leave the worker running. The first run downloads weights. Verify `http://127.0.0.1:8174/health` returns HTTP 204. CPU works but is slower. For GPU acceleration, use CUDA-enabled PyTorch with a compatible NVIDIA driver; confirm the worker reports `cuda` at startup. If local voice is skipped, use the browser voice and leave the local setting disabled. Groq is still needed for Safi's responses and Auto transcription.
5. **Start and verify Tiryaq.** Run `dotnet dev-certs https --trust` if needed and let the teammate approve any trust prompt. Run `dotnet run --launch-profile https` and verify [https://localhost:7130](https://localhost:7130) responds. When an authorized login is available, open Safi, allow microphone access, and check for **Chatterbox** on the orb during playback. Report whether the app, voice worker, and signed-in voice flow were verified. If a step is blocked, state the exact missing prerequisite and complete the rest.
